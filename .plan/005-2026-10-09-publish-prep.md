## Risks
- **Screenshots leak personal data.** A screenshot of the running app can show a browser tab, a
  bookmark, a user name, or a file path. Step 3 opens each image and stops if anything beyond the
  app is visible. A PNG can also carry text metadata; the owner exports the images from a
  screenshot tool, not from a document, and Step 3 does not edit them.
- **The README overclaims.** A public README read as a portfolio piece can drift into "live" or
  "production" wording. Step 3 and Validation grep for it; the README keeps saying it is a local
  project.
- **Agent docs drift from the hook.** Step 4 changes what the `frontend`, `backend`, `qa`, and
  `orchestrator` agents are told. The two lines that mirror the hook (`frontend.md:31`, `qa.md:20`)
  stay unchanged, and Validation checks that `.claude/hooks` and `.claude/settings.json` did not
  change. If an agent later runs, it reads the contract from `.doc/architecture.md`, which is
  where it already lives.
- **New wording matches its own check.** In plan 004 Step 3, a replacement matched the cleanup grep
  and had to be rewritten. Every Step 4 replacement here was tested against all three greps before
  it was written into this plan.
- **`backend/.gitignore` misses a real file.** If Step 2 finds no output, nothing is added (Q6). A
  later change that starts producing such a file (coverage, `incremental`) must add its pattern
  in the same commit; `git status --short` in every hand-off shows any stray file.
- **The author check depends on local config.** If `user.email` changes before a commit, that
  commit carries a different address. The Q4 check runs after every commit, before the next step.
- **Going public is one-way in practice.** Once public, the code can be cloned, forked, or cached
  even if the repository is made private again. That is why the scan is repeated right before the
  switch (Rollout), not only during this plan.

## Rollback
- Every step is its own commit, so any one can be undone with `git revert <commit>` without touching
  the others. No step changes runtime behavior, so a revert needs no restart or reload.
- Before merge: `git restore --staged` and `git restore` the step's files, or drop the
  `chore/publish-prep` branch and recreate it from `main`.
- After merge: `git revert` the merge commit, or only the commit of the step that is wrong.
- Screenshots: reverting Step 3 removes the images from the tree but not from history. If an image
  is found to leak personal data **before** the repository is public, rewrite the branch before
  merging; if **after**, make the repository private again first, then decide on a history rewrite.
- Visibility (manual Rollout): Settings → General → Danger Zone → Change visibility → Make private.
  Stars and watchers are lost, and copies already cloned or forked remain.
- Set this plan to `superseded` or back to `draft`, and uncheck the backlog item if it was checked.
