# 001 — Chat proxy: streaming and system prompt

Status: active
Owner: Idan
Last updated: 2026-10-08

Backlog task: `chat backend: proxy with streaming and system prompt | stack:full`

## Goal
Stand up the `backend/` proxy: a local Express server that takes a `chat` from the
browser, adds the `tutor` system prompt, streams the Anthropic response back in
increments, and keeps `ANTHROPIC_API_KEY` on the server. The chat UI (next backlog
task) is built against the API contract this plan defines.

## Scope
In scope:
- New `backend/` package: Node.js 22.12, TypeScript, ESM, Express 5, `@anthropic-ai/sdk`.
- One route: `POST /api/chat`, streaming over Server-Sent Events (SSE).
- `GET /api/health` for liveness. The e2e setup and the dev scripts use it to wait for startup.
- The system prompt module and its unit test (AC05).
- Input validation, upstream error mapping, and a uniform error shape per the `error-handling` skill.
- CORS limited to `FRONTEND_URL`. Bind to `127.0.0.1` only.
- Vitest + Supertest suites. The Anthropic client is mocked, so tests never touch the network.
- The API contract, written only in `.doc/architecture.md` (no `.orchestrate/api-contract.yaml`).
- `backend/.env.example` and the `.doc/` updates.

Out of scope:
- Anything in `frontend/` (next backlog task).
- Quiz generation and `/api/quiz` (third backlog task).
- Persistence, accounts, auth, rate limiting by user, and deployment. These are out of product scope.
- Prompt caching and token-cost tuning. Revisit only if usage warrants it.

## Assumptions
- The `chat` is stateless on the server. The browser sends the full message history on every
  request. There is no database (product scope).
- The stack is the one in `.claude/agents/backend.md`: Node 22.12 + TS + ESM, Express 5, Vitest + Supertest.
- There is no root `package.json`. `backend/` is a self-contained package with
  `"type": "module"` and its own `tsconfig.json`.
- Requests use the official `@anthropic-ai/sdk` with `client.messages.stream(...)`. No raw `fetch`.
- The SDK's built-in retries (default `maxRetries: 2`, covering 408/409/429/5xx and connection
  errors) are the only retry layer. That satisfies the skill's rule of bounded retries on transient
  errors only. The proxy adds no retry of its own.
- The app is built by a factory, `createApp({ client, config })`, so tests can inject a fake Anthropic client.
- The model is `claude-haiku-4-5` by default. Requests send no `thinking` and no `output_config.effort`;
  Haiku 4.5 rejects `effort`, and thinking is off when `thinking` is omitted.
- The backend agent reads the contract from `.doc/architecture.md` instead of
  `.orchestrate/api-contract.yaml`. It already has read access to `.doc/**`.

## Open Questions
All questions are answered (2026-10-08). The steps below reflect the answers.

1. **Model.** Which model does the tutor use?
   Recommended: `claude-opus-5-5`, overridable with an optional `ANTHROPIC_MODEL` env var.
   Answer: `claude-haiku-4-5` by default, overridable with an optional `ANTHROPIC_MODEL` env var.

2. **Effort.** Claude Opus 5.5 always thinks, and `output_config.effort` controls how much
   (its default is `medium`). A chat tutor needs fast first tokens.
   Recommended: `effort: "low"`, overridable with an optional `ANTHROPIC_EFFORT` env var.
   Answer: Removed from the plan. No `effort` setting and no `ANTHROPIC_EFFORT` env var.

3. **Message role names in the contract.** The glossary calls the AI `tutor`, and the Anthropic API calls it `assistant`.
   Recommended: the contract uses `"user" | "tutor"`, and the proxy maps `tutor` to `assistant`.
   Answer: As recommended.

4. **Stream format.** SSE (`text/event-stream`) with typed events, or plain chunked text?
   Recommended: SSE with three events: `delta` `{ text }`, `done` `{}`, and `error` (standard
   error shape). SSE is the only one of the two that can report a failure after the stream has started.
   Answer: As recommended.

5. **Abuse limits.** These cap API spend per request. Hard limits on the request body:
   Recommended: at most 50 messages, at most 8,000 characters per message, and `max_tokens` 4,096.
   Answer: As recommended.

6. **API contract authorship.** `.claude/agents/backend.md` expects the frontend agent to write
   `.orchestrate/api-contract.yaml`, but here the backend comes first. In addition, `.orchestrate/` is gitignored.
   Recommended: the orchestrator writes the contract as Step 1 of this plan. The durable copy
   lives in `.doc/architecture.md`.
   Answer: The contract lives only in `.doc/architecture.md`. No `.orchestrate/api-contract.yaml`.

## Steps
1. **Branch.** Create `feat/chat-proxy` from `main` after this plan is approved.
2. **API contract.** Write the contract into a `## API Contract` section of
   `.doc/architecture.md`. This is the only copy; do not create `.orchestrate/api-contract.yaml`.
   It must cover:
   - `POST /api/chat`: request `{ messages: { role: "user" | "tutor", content: string }[] }`.
     Success: `200 text/event-stream` with events `delta` / `done` / `error`.
     Failures before the stream starts: JSON in the standard error shape.
   - `GET /api/health`: returns `200 { status: "ok" }`.
   - Every response carries an `X-Request-Id` header.
3. **Scaffold `backend/`.** Add `package.json` (`type: module`, scripts `dev` (tsx watch),
   `build` (tsc), `start`, `test` (vitest run), `typecheck` (tsc --noEmit)), `tsconfig.json`
   (strict, NodeNext), and `.env.example` with `ANTHROPIC_API_KEY=`, `FRONTEND_URL=http://localhost:3000`,
   `PORT=4000`, and optional `ANTHROPIC_MODEL=`.
4. **Config.** Add `backend/src/lib/config.ts`. It reads and validates env vars at startup and fails fast
   with a clear message if `ANTHROPIC_API_KEY` or `FRONTEND_URL` is missing. `model` defaults to
   `claude-haiku-4-5` when `ANTHROPIC_MODEL` is unset. It never logs the key value.
5. **System prompt.** Add `backend/src/lib/system-prompt.ts`, which exports a frozen `SYSTEM_PROMPT` string.
   The prompt tells the tutor to:
   - guide with questions and hints rather than complete solutions, unless the user explicitly
     asks for the full solution;
   - give one question or one hint at a time;
   - not point to the exact line or the exact fix;
   - give a bigger hint when the user is stuck;
   - explain concepts when the user asks;
   - reply in English only, and keep replies short;
   - use Markdown with fenced code blocks.
6. **Validation.** Add `backend/src/lib/chat-request.ts`, a `zod` schema for the request body.
   Rules: non-empty array; roles from the contract; non-empty trimmed `content`; the limits from
   Q5; first and last message from `user`; roles alternate. A violation returns `400`
   `validation_error` with field details.
7. **Chat service.** Add `backend/src/lib/chat.service.ts`. It maps messages to the Anthropic
   format, calls `client.messages.stream({ model, max_tokens: 4096, system: SYSTEM_PROMPT,
   messages })`, and yields `text_delta` text. It sends no `thinking` and no `output_config`.
   It exposes an abort handle.
8. **Route.** Add `backend/src/route/chat.ts`, which wires validation, the service, and SSE:
   - Wait for the first upstream event before sending SSE headers. That way a failure at connect
     time becomes a proper HTTP status with the standard error shape.
   - Error mapping, most specific first: `Anthropic.RateLimitError` → `429 upstream_rate_limited`;
     `AuthenticationError` / `PermissionDeniedError` → `500 proxy_misconfigured`, logged as a
     config error; `APIConnectionError`, `InternalServerError` and other `APIError` → `502 upstream_unavailable`.
   - A failure after headers are sent produces one SSE `error` event, then the response ends.
   - A `refusal` stop reason produces an SSE `error` with code `tutor_refused`.
   - If the client disconnects (`req` `close`), abort the upstream stream so it stops spending tokens.
9. **App and server.** `backend/src/app.ts` exports `createApp`, which sets up JSON body limit,
   request-id middleware, CORS (`FRONTEND_URL` only), routes, a 404 handler, and the final error
   handler. `backend/src/index.ts` builds the real client and listens on `127.0.0.1:PORT`.
10. **Logging.** Structured `console` JSON lines with `requestId`, operation, status, and upstream
    error type. Never log message content, headers, or the key.
11. **Tests** (`backend/tests/`, per `writing-tests`): see Validation. Also add
    `backend/tests/fixtures/smoke-chat.json` (one `user` message: "why is my loop infinite?")
    as the request body for the manual smoke test.
12. **Docs.** Fill the rest of `.doc/architecture.md` (components, data flow, error mapping,
    change log entry), and update the `## API Contract` section if implementation changed it. Add a short `backend/README.md` covering setup and run.
    Check `.doc/glossary.md` and add terms only if a new shared term appeared.
13. **Report.** Write `.orchestrate/backend-agent-report.md` per the backend agent's format.

## Risks
- **Credit abuse.** Anyone who can reach the port can spend the key. Mitigations: bind to
  `127.0.0.1`, restrict CORS, enforce the body limits from Q5, and keep `max_tokens` capped.
- **System prompt is soft.** The model may still hand over full solutions. AC05 only proves the
  prompt is sent, not that the model follows it. Behavior quality is checked by the manual
  smoke test and can be tuned later.
- **SSE behind proxies or buffering.** Compression or buffering middleware can batch chunks and
  break AC02. Do not add compression, set `Cache-Control: no-cache`, and flush headers.
- **Errors after streaming starts** can't change the HTTP status. The SSE `error` event covers
  this, and the frontend must handle it (noted for task 2).
- **Model choice.** Haiku 4.5 is fast and cheap but weaker at holding back full solutions.
  `ANTHROPIC_MODEL` allows switching without a code change. A newer model may need request
  changes; for example, Opus 5.5 always thinks.
- **Contract drift.** The backend agent's definition still points at `.orchestrate/api-contract.yaml`.
  The orchestrator must point it at `.doc/architecture.md` in the handoff for this plan.
