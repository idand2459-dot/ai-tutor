## Open Questions

1. **Default model (product decision).** `backend/src/lib/config.ts` defaults to `claude-haiku-4-5`
   for both routes.
   Recommended: **B — `claude-sonnet-5-5` as the default for both routes**, with `ANTHROPIC_MODEL`
   still able to switch back. Trade-off: the manual runs already show better quizzes (and the
   stronger model should hold back full solutions better), but every chat reply and every quiz
   costs more and the first streamed token arrives later.
   - A: keep `claude-haiku-4-5`. Cheapest and fastest; quiz quality stays at the level the manual
     runs found weaker. Step 9 then changes only the docs (the decision and its reason).
   - C: keep Haiku for chat and add `ANTHROPIC_QUIZ_MODEL` defaulting to `claude-sonnet-5-5` (plan
     003 Q8's alternative). Best quality per cost, but a new env variable, new config tests, and a
     second model to document.
   Answer (2026-10-09, owner): B (`claude-sonnet-5-5` as the default for both routes) — approved as recommended.

2. **`tutor` message length cap (product decision).** Today every `message` is capped at 8,000
   characters, but a `tutor` reply may be up to 4,096 tokens, which can be more than 8,000
   characters, so the next `/api/chat` or `/api/quiz` request fails with `400 validation_error`.
   Recommended: **A — a per-role cap: `user` stays at 8,000; `tutor` gets 24,000** (about 6
   characters per token of the 4,096-token limit). Trade-off: no valid reply can break the `chat`
   any more, but a long `chat` sends more input tokens per request; the 2 MB body limit still holds
   (at most 25 × 24,000 + 25 × 8,000 = 800,000 characters).
   - B: lower `max_tokens` for chat to about 2,000. Keeps one cap, but long explanations get cut off
     mid-sentence, and a `max_tokens` stop would need its own handling in the UI.
   - C: trim long `tutor` messages in the browser before sending. No contract change, but the model
     silently loses part of the `chat`, and the quiz may miss a topic.
   Answer (2026-10-09, owner): A (`tutor` cap 24,000; `user` stays 8,000) — approved as recommended.

3. **The three backend items have no `| stack:full` marker.** The `writing-plans` skill says not to
   plan backend work without it. The tutor cap, the role-alternation refactor, and the default model
   all live in `backend/`, which plans 001 and 003 (both `stack:full`) built.
   Recommended: **treat them as `stack:full`**. On approval, Step 1 appends `| stack:full` to those
   three backlog lines, so the backlog matches the plan. Alternative: drop Steps 5, 8, and 9 from
   this plan and leave those items in the queue.
   Answer (2026-10-09, owner): treat the three backend items as `stack:full` — approved as recommended.

4. **How to render inline code in `option` text.** Options are plain text inside a `<label>`
   (plan 003 Q6), so `` `map()` `` shows its backticks.
   Recommended: **a small inline-code splitter**: a pure function `splitInlineCode(text)` that
   returns text and code segments for single-backtick pairs, rendered as text and `<code>` inside the
   existing `<span>`. An unmatched backtick stays literal. Nothing else is parsed, so `a*b*c` and
   `_x_` in an `option` stay exactly as written, and no HTML is ever built from model output.
   Alternative: `react-markdown` limited to `code` (`allowedElements`, `unwrapDisallowed`). Reuses
   the Markdown parser, but it also consumes `*`, `_`, and `\` around unwrapped emphasis, which
   would silently change `option` text such as `a*b*c`.
   Answer (2026-10-09, owner): the inline-code splitter — approved as recommended.

5. **Where focus goes after "Retake quiz".** The button unmounts (it is replaced by "Check answers",
   which is disabled until all 5 are answered), so focus falls back to `<body>`.
   Recommended: **the first radio of question 1.** The user starts answering again from the top,
   arrow keys work at once, `focus()` scrolls the view back up, and a screen reader announces the
   question group. Focus moves only on the change from checked to not checked, never when the quiz
   first opens. Alternative: the "Quiz" heading (with `tabIndex={-1}`). It announces the view, but
   it takes one more Tab to reach an answer.
   Answer (2026-10-09, owner): the first radio of question 1 — approved as recommended.

## Rollback
- Every step is its own commit, so any one can be undone with `git revert <commit>` without touching
  the others. Steps 4 and 5 are pure refactors; reverting them restores the duplicated code and
  changes nothing a user sees.
- Before merge: `git restore --staged` and `git restore` the step's files, or drop the
  `chore/polish-backlog` branch and recreate it from `main`.
- After merge: `git revert` the merge commit, or only the commit of the step that misbehaves.
  Step 9 can also be undone without a code change: `ANTHROPIC_MODEL=claude-haiku-4-5` in
  `backend/.env`.
- Reverting Step 8 brings the 8,000-character `tutor` limit back; a `chat` that already holds a
  longer `tutor` reply would then fail its next request again (the original bug), so revert Step 8
  only together with a page reload.
- Set this plan to `superseded` or back to `draft`, and uncheck any backlog item that was checked.
